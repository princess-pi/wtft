Token Budget Utility (token-budget.ts)

Domain: Quota Management, Proactive Rate Limiting & Cooldown Breaks

Overview

The Token Budget extension prevents the agent from breaching model subscription quota limits (TPM - Tokens Per Minute). It runs transparently in the background, intercepting provider requests to check sliding-window usage metrics across all active local agent sessions. When a safety threshold is crossed, it enforces a 40-second synchronous "coffee break" (cooldown) to let API quota windows reset safely, notifying the user and maintaining a lockfile for external status bar / tmux integration.

Specification & Mechanisms

1. Quota Safety Limits

We maintain a hardcoded quota safety registry mapped to model shortcodes, configured to roughly 80% of actual provider subscription tiers to ensure a conservative buffer:

  • g3.5fla, glatfla, g3.5fli, glatfli: 2,500,000 TPM (Tier 2 limit: 3.0M)
  • g1.5pro, glatpro: 1,600,000 TPM (Tier 2 limit: 2.0M)
  • c3.5son, c3.5hai: 320,000 TPM (Tier 4 limit: 400K)
  • c3.0opu: 80,000 TPM

2. Active Session Log aggregation

Token Budget scans the wtft-tags/ tag files (the .wtft-tag.vX.Y.Z.jsonl records) under ~/.claude/projects/ and ~/.pi/agent/sessions/, updated within the last 2 minutes, to aggregate total TPM across all parallel agent sessions.

3. Schema & Token Counting

Token Budget reads the classified wtft tag files — .wtft-tag.vX.Y.Z.jsonl records under wtft-tags/ — never raw provider .jsonl session logs. The wtft daemon has already normalised every harness's transcript into one record shape (docs/wtft-tag-format.md §2a), so there are no per-provider schemas to parse:

wtft tag interaction line (classified): 
{
  "t": 1756897200000,        // Unix ms — recency filter
  "c": 0.004231,             // cost USD
  "cat": "agent",            // pre-classified category
  "m": "claude-3-5-sonnet",  // model name → quota shortcode
  "in": 5472,                // input tokens
  "out": 375,                // output tokens
  "cr": 25347,               // cache-read tokens
  "cw": 0                    // cache-write tokens
}

Heartbeat lines (a top-level _hb key) are skipped, and a record is counted only when it carries a model (m) and a timestamp (t). Input tokens are the sum of in + cr — cache reads bill against the same quota window, so they count toward the budget.

4. Aggregation Rules

Only records from the last two minutes are considered, and only those within the last one minute accrue TPM (the sliding window). Each record maps its model name to a quota shortcode and adds its input tokens:

const age = Date.now() - obj.t;
if (age > 120_000) continue;                  // older than 2 min — ignore
const shortCode = getModelShortName(obj.m);
const inputTokens = (obj.in || 0) + (obj.cr || 0);
if (age <= 60_000) {
  modelStats[shortCode].tpm += inputTokens;   // 1-minute TPM window
}

5. Live Cooldown Countdown

To ensure maximum visibility and a highly responsive user experience, the extension does not passively block the harness thread during a coffee break. Instead, it executes a 1-second interval loop that dynamically decrements the remaining cooldown seconds and live-refreshes the Pi TUI widget content in real-time, displaying a decrementing sequence of 8 coffee cups representing the 40-second block (one cup per 5s): [☕☕☕☕☕☕☕ ] 35s remaining.... This runs in perfect synchrony with the external tmux status bar.

Tmux Status Bar Integration

Token Budget integrates seamlessly with your terminal environment by utilizing a light, fast lockfile standard:

  • Mechanism: When a coffee break cooldown is initiated, the extension writes an ephemeral JSON file to /tmp/pi-rate-limit-coffee.json containing the cooldown's startTime and endTime.
  • How It Updates: Under the Pi TUI Widget, the countdown live-refreshes every 1 second directly on-screen. Under the tmux status bar, an external script (budget_meter.js) reads the JSON file synchronously on a fixed client status interval (typically 5 seconds), rendering decrementing coffee cups (☕☕☕ ) and remaining seconds.
  • How to Enable/Disable:
    • To Enable: Configure your .tmux.conf to execute the helper script (e.g. set -g status-right "#(node ~/.config/tmux/budget_meter.js)") and set set -g status-interval 5.
    • To Disable: Comment out or remove the status-right script reference in your .tmux.conf and reload tmux configuration.

Architectural Scope & Quota Isolation Boundaries

1. Single Host / Local User Limit:

Because the Token Budget aggregates rolling TPM by reading the wtft-tags/ tag files stored under local home folders (~/.claude/projects/ and ~/.pi/agent/sessions/), rate limits are only computed and tracked for active sessions running under the same user account on the same local host machine. There is no inter-host, inter-machine, or network-level tracking for other development machines or autonomous services sharing the same model API key.

2. Best Practices & Isolation Workarounds:

  • Separate Accounts/Dev Keys: Developers on different machines should always use distinct Google/Anthropic API keys or separate subscription project scopes to avoid unexpected quota collisions.
  • Isolate Autonomous Services: Background autonomous agents running in production must be separated onto isolated accounts/tiers. This ensures that heavy local developer activity does not trigger limit cooldowns that lock out critical production workflows (or vice versa).
